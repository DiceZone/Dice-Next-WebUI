# Dice!Next WebUI

  <a href="README.md">English</a> · <a href="README.zh-Hans.md">简体中文</a> · <a href="README.zh-Hant.md">繁體中文</a> · <b>日本語</b>
</p>

Dice!Next のローカルの管理画面のフロントエンドです。バックエンドの API と通信し、ボットの接続の設定、グループとユーザーの管理、ルールパックとプラグインの保守、セッションのログとセッションのデータの確認に使います。

## 機能の範囲

- ダッシュボード、システムの設定、アダプターの接続の管理。
- グループ、ユーザー、権限、チャットの模擬の管理。
- キャラクターシート、ルールパック、JavaScript / Lua プラグイン、データの管理。
- セッションのログの表、セッションのカード、ログの書き出しとアップロードの操作。
- 簡体字中国語、繁体字中国語、英語、日本語の画面。

ホームのサーバーの情報の下にある「よく使う操作」はカスタマイズできます。右上の調整のボタンを押し、最大 6 個のページの入口を選び、上下の矢印で並べ替えてから、保存するか既定に戻します。この設定は現在のブラウザーに保存され、ボットの設定は変えません。ブラウザーのサイトのデータを消すと既定に戻ります。全体の検索で「よく使う操作」を探してもここに移動できます。

## 技術の構成

- React 18
- TypeScript
- Vite 6
- Tailwind CSS と Radix UI
- TanStack Router / Table

## 開発

必要な環境：Node.js 26.12.1 またはそれより新しい 26.x の安全な版と、付属の npm。
CI は `26.x` を使い、最新の版を強制的に確認します。ビルドの前に最低限の安全な版を検証し、実際の版を記録します。

```powershell
npm ci
npm run dev
```

開発用のサーバーが起動すると、ローカルのアドレスが表示されます。実際の API は Dice!Next のバックエンドが提供するので、先にバックエンドを起動するか、開発の環境で接続できるバックエンドのアドレスを設定してください。

## 確認とビルド

独立した GitHub Actions が push / PR のときにテスト、型の確認、本番のビルド、PWA の成果物の確認を実行します。フロントエンドだけを確認し、バックエンドのコンパイル、公開、導入は行いません。

独立したプレビュー `npm run dev:preview` は実際のボットにつながりません。実際の文章のシリアライズの結果を見たい場合は、メインのリポジトリの `tools/reply-preview.cpp` をコンパイルし（`markdown.cpp`、`markdown_md4c.cpp`、MD4C、nlohmann JSON をリンク）、実行ファイルの絶対パスを `DICENEXT_UI_PREVIEW_RENDERER` に入れてください。設定していない場合はプレビューが使えないことをはっきり表示し、簡単な正規表現でプラットフォームの出力を偽ることはしません。

```powershell
npm run lint
npm run build
```

`npm run build` は `dist/` を作ります。このフォルダーはメインのプログラムのパッケージの作成の流れで Windows、Linux、macOS の配布パッケージに取り込まれるので、リポジトリにはコミットしないでください。

## アプリとしてのインストール

WebUI はアプリのマニフェストを提供しており、この機能に対応したブラウザーで独立した窓のアプリとしてインストールできます。

- Chrome / Edge：アドレスバーのインストールのアイコン、またはブラウザーのメニューのアプリのインストールの入口を使います。入口の名前と表示の時期はブラウザーが決めます。
- macOS の Safari 17 以降：「ファイル」メニューで「Dock に追加」を選びます。
- iPhone / iPad：ブラウザーの共有のメニューで「ホーム画面に追加」を選びます。

HTTPS か、ローカルの `http://localhost:ポート` / `http://127.0.0.1:ポート` を使ってください。通常の HTTP の LAN や公開の IP では、ブラウザーがインストールを勧めるための安全の要件を満たしません。そのためにブラウザーの安全の制限をオフにしないでください。

インストールされるのは現在のアドレスの管理パネルで、ボットのバックエンドではありません。バックエンドは引き続き動かす必要があり、ログインの確認も変わりません。この機能は Service Worker を登録せず、オフライン / API のキャッシュも加えず、オフラインの管理やバックグラウンドでのボットの実行も提供しません。サーバーのアドレスが変わったときは、新しいアドレスからインストールし直してください。

アプリのアイコンは `public/favicon.svg` を使い回しています。このアイコンを置き換えた後は `npm run icons:generate` を実行し、生成された `public/icons/` のファイルをコミットしてください。ビルドの後に `PWA_TEST_DIST=1 node --test tests/pwa.test.mjs` を実行すると、配布のリソースを確認できます。

## ほかのプロジェクトとの関係

ブラウザーの回帰テストは常にリポジトリ内の独立した例を使い、同じ階層のリポジトリを自動で読まないため、ローカルと CI のデータが一致します。
`node tests/ui-preview.mjs` で同じ例を手動で確認できます。`npm run dev:preview` は明示的に
`--workspace` を有効にし、同じ階層のメインのプログラムと文書のリポジトリが使えるときは完全なコマンドと文章を読みます。どちらのモードも実際のボットにはつながらず、
変更はプレビューのプロセスの中だけに残ります。

このプロジェクトは `Dice-Next`、`Dice-Next-Doc`、`onedice-cpp-lib` と同じ作業領域で開発しています。バックエンドのパッケージの作成では `DICENEXT_WEB_ROOT` でこのプロジェクトの `dist/` を見つけます。この変数を設定していない場合は、既定で同じ階層の `Dice-Next-WebUI` を読みます。
